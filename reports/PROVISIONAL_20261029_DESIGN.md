## Step 4: unverified assistance and independent review preparation

Reused recovered packets receive exact construction spans and limited literal or
lexical source-support suggestions. Every suggestion remains semantically unverified.
Lexical overlap is neither authenticated authorship nor a security decision.

Simple phrase rules separately flag possible instruction overrides, verification
bypasses, outgoing transfers or claims of privilege. Exact matched record offsets
are saved. Quoted attacks and negated instructions can trigger these rules; unflagged
records are not assumed safe. There is no confidence/probability or verified verdict.

Warning hints stay in a separate private curator file. They are **excluded** from
the initial blinded reviewer packets and do not determine packet order, source
selection, contributor identity, permission, audit feedback or ground truth. Human
forms start with blank identities and null provenance/safety decisions. Reviewer 3
is only for genuine disagreements after two independent initial reviews.

## Step 5: improved question drafts

Reuse existing questions, refine suitable copula-question grammar without changing
reference values, add limited whole-statement drafts only when the existing claim
is literally present in the external source, and deduplicate equivalent questions.
At most three candidates per contribution are exported. Keep exact source spans,
memory IDs and content versions. Mechanical checks reject answer leakage, unsupported
literal references and broken spans; quality flags identify broad questions,
negation/quantifier cases, short references, length and blocked chunk-only support.

All outputs remain safety-unverified, unvalidated and ineligible for a final benign
set. Human judgment is still needed for semantic entailment, provenance, clarity,
usefulness and safe use. The frozen external_evidence=false restriction remains;
external-chunk-only drafts cannot become final usable utility probes under that
setting. A mechanically checked draft is not a human-validated answer or question.

## Step 6: exact development recipe

Prepare 20 disjoint 32-case groups, using the already inventoried and mechanically
recovered Email/File-Document population. Use neither warning flags, question
availability/quality, inferred safety nor historical attack success for selection.

Require one contribution per duplicate/template component across all 20 groups.
Exclude components already flagged oversized until a real manual approval exists.
No approval is invented. A deterministic bipartite augmenting-path allocation
matches components to required context/stratum slots, avoiding greedy starvation
of scarce explicit-benign cases. Candidate edge order is a seeded content hash;
slot priority uses component availability relative to required stratum capacity.
If the exact quotas are infeasible, fail rather than weaken them or reuse cases.
This is a declared controlled sample, not a uniform population sample.

Group IDs D00–D07 are development; D08–D19 are provisionally reserved for later
review. These names do **not** establish a locked, independent confirmatory test.
Public group/episode tokens and metadata IDs are HMAC-blinded using the existing
private identifier key; source/question/quote text is unchanged. No key is copied
to a defense-visible file.

Each group has two synthetic contributors, two real contexts, and two submission
batches of four contributions per contributor/context. Both contributors have the
same collaborator role and initial all-allow policy. The original task principal
remains `user`. Synthetic contributor assignment concerns external origins, not
principal-authored memories. No natural author is authenticated from a signature.
Batch membership is a grouping relationship, not derivation or a deduplicated copy.

Use the existing six source/batch weight cells: (9,1), (9,9), (2.25,1), (2.25,9),
(1,1), (1,9). Within each context, draw **ten attack-input slots** from sixteen
positions with exact probability proportional to the product of their weights,
using the existing integer subset sampler. The earlier verified pilot's eight
unsafe-memory slots are not used or silently relabeled. Uniformly permute attack
inputs and benign inputs into their respective chosen slots. Contributors' realized
case-intent rates vary naturally; do not reject pure batches or force equal rates.
Hidden high/hot profiles are private and alternate high source across contexts.
Reported association is with input-case intent, not actual memory risk.

Keep COMMON seeded ingestion and base query orders, independent of overlay positions.
All six metadata overlays reuse the same 32 payloads. All four future arms R/C/M/S
reference the same serialized source/overlay/event digest within each condition;
none of their policies is implemented here.

Relationally chosen audit IDs can differ across overlays. Comparisons between

It is separate from the primary all-allow metadata and is not a completed ACL defense.
