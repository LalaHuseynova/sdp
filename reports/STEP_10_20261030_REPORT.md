# Step 10: sequential execution and restart validation

30 October 2026. **Step 10 is implemented and validated within the offline research
scope.** The harness executes original SAFE-Mem writes, integrated retrieval and
optional typed answering using explicitly supplied frozen responses. It restores
complete supported runtime state and continues at the saved event boundary.
**Paid API calls: 0. Paid cost: $0.** No MPBench efficacy evaluation, model download,
training, independent human annotation or final scientific pilot was performed.

## Completed behavior

**Sequential order and information boundary.** The controller dispatches one
action when it is available; the runner never accepts a complete future-feedback
schedule. Reveals must use their current reveal time. A query cannot inject old
permission/evidence snapshots. Backdating after a committed query is refused;
equal-time actions retain their explicit order. Answers do not update trust.
Extra case-gold/expected-memory fields and pending audit jobs are rejected.

**Complete supported state.** Checkpoints preserve claim/source/entity contents,
order, lookup lists, source sentence links, contested flags and native ID counter;
claim/chunk and entity-name vector rows/ID order; chunks and source parents;
memory settings/counters; original query-classifier rungs/subjects/unparsed state;
client/prompt-library aliases; exact replay tables and actual call history;
binding and permission versions; evidence/incident state and audit budgets; RNG
state; logical clock and saved results. Derived vector matrices rebuild from their
preserved rows. Unsupported partitioned state is refused rather than dropped.

**Response and decision replay.** Each completed call is durably recorded before
its return is consumed. The journal saves the full request, literal response text,
provider/cache metadata, raw finish reason, reported native usage or literal error.
Query outputs save actual retrieved contexts and the original 200-token typed
answer request. A `length` finish remains visible and flagged; it is not rewritten
as a complete answer. Saved responses take precedence over later cache values.

**Interruption handling.** Intent, call and commit rows are separate and immutable.
If a process stops after a saved response but before committing its step, recovery
restarts from the previous committed state and consumes the saved request/response
prefix exactly once. A changed request sequence stops recovery. Repeating a
committed action ID/payload returns its stored result; conflicting reuse fails.

**Failures and resources.** A failed action remains `status="failed"`, with its
partial retrieval/write information and error. Graph, indexes, classifier, ACL,
evidence and RNG changes roll back, while attempted-call histories remain charged.
Committed-state accounting and all durable calls—including pending-step calls—are
available separately. Missing-response usage stays explicitly unknown. Verification
ticket accounting is separate from extraction/classification/conflict/answer replay.
Neither corrections nor restart refund spent audit tickets.

**Writes after restart.** Original `write` executes at the dispatched event with
frozen extraction/embedding replies. A trusted writer policy and append-only
binding/graph checks apply. New artifact grants may extend unchanged old grants
under the same policy version; changing earlier grants requires a fresh version.
This preserves old use-specific reviews when merely adding an isolated artifact.
The runtime does not infer authorship from lexical overlap or fabricate annotations.

**Persistence checks.** Runs enforce an exclusive writer, SQLite full synchronous
commits and integrity checks, chained row hashes, prompt-file fingerprints and
code/environment checks. Checkpoint restore uses a fresh destination and verifies
its database checksum, cursor, commit head and resources. An older checkpoint
cannot acquire later events from its source run. Existing outputs are never overwritten.

## Validation evidence

**223 relevant tests passed: 176 earlier checks plus 47 new sequential checks.**
Targeted Ruff lint and formatting checks passed.

The new checks include:

- R/C/M/S restart comparisons at five boundaries, with output/state/resource parity.
- Preservation of contested flags, classifier cache, client/library aliases,
  vector scores, native IDs, original sentence/chunk links and entity-name indexes.
- Original writes after restore with matching IDs, vectors, provenance and results.
- Interruption after intent, after either saved call, before commit and after commit.
- Separate-process checkpoint restoration and **abrupt process exit** after saved
  calls, without graceful close. The next process acquires the writer and recovers.
- Pending successful and failed calls counted once, including a failed cache miss.
- Literal answer/finish-reason capture, original prompt and token limit, and a saved
  response overriding a different later cache value.
- Partial conflict-state rollback on answer failure, denied/misbound write rollback,
  audit-budget exhaustion, delayed feedback and permission-version enforcement.
- Rejection of corrupt/truncated checkpoints, altered call rows, code/environment/
  prompt drift, divergent recovery requests, stale contexts, multiple writers and
  unjournaled in-memory mutation.

## Preservation and scope limits

A before/after check covered **952 pre-existing files**; none changed. This includes
earlier source/scripts/tests/configs/prompts, local datasets, reports and research
outputs. Old caches/results, vendors, environments, bytecode and PDFs were outside
the inventory and were not used by this implementation. Pre-existing working-tree
edits were preserved; no staging or commit was performed.

The previous provisional validator still passes **306 files, 20 groups and 120
overlays**. Independently verified human safety labels remain zero and the final
scientific pilot remains unready. No old extraction/recovery/group generation or
review import was rerun.

Tests and reports remain subject to the repository's existing ignore rules.

Important limits remain explicit:

- This validates **offline** execution. Live SDK clients are refused. A live request
  that completes before durable response capture can have an unknown billing
  outcome; that needs a separately validated provider/accounting adapter. No
  exactly-once live API billing guarantee is claimed. API latency is not measured.
- This snapshots newly constructed research graphs; it does not reconstruct an
  unavailable complete historical SAFE-Mem graph from recovered text records.
- Checkpoints assume the same validated code, prompt files and execution environment.
  Portable migrations and hardware/power-loss behavior were not established.
  Hashes are integrity checks, not authentication against a host rewriting all files.
- Full state is saved per commit for correctness. Storage/throughput optimization
  is needed before large full-release runs. No full MPBench benchmark was executed.
- The harness is not an authentication system, adaptive audit service or OS sandbox.
  Trusted preparation must supply genuine provenance and valid audits, redeem only
  authorized tickets, and isolate evaluator data. No target judge is wired into trust.
