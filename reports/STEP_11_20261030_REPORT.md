## Conditional API-cost estimate

The [official OpenRouter model page](https://openrouter.ai/openai/gpt-4o-mini/overview)
lists **$0.15/M input and $0.60/M output** for the planned model. These rates were
checked on 30 October 2026 and matched the existing local rate configuration.
Future dispatch must recheck the model/context/rate conditions and enforce the
existing maximum-rate/no-higher-price-fallback restrictions.

| Scope | Working estimate, including 20% retry allowance | Stress estimate: two attempts plus 25% headroom |
| --- | ---: | ---: |
| Eight development bags | $5.32–$5.93 | $42.49 |
| Twelve locked-primary bags | $7.99–$8.89 | $63.74 |
| Combined twenty bags | **$13.31–$14.81** | **$106.23** |

**Proposed combined stop limit: $125, not activated.** These are conditional
planning scenarios, not measured token usage, a confidence interval, an assured
bill or a guarantee that the run finishes within the limit. Working assumptions
use one conflict check per memory question and stage-specific input lengths.
Stress uses six checks per k=4 query, larger input assumptions, the frozen output
ceilings, two physical attempts per logical call and extra headroom.

The count endpoints are combined conservatively; the separate maxima need not all
occur together. The JSON also reports the much larger **$3,298.01** full-context,
all-attempts reservation calculation for the combined scope. The proposed $125
limit is a stop condition, not permission to exceed it or a full worst-case
completion budget. Incomplete/budget-stopped questions must remain visible.

Detailed [stage costs and assumptions](../research_data/dynamic_pilot_plan_v2_20261030/COST_ESTIMATE.md)
and [machine-readable estimates](../research_data/dynamic_pilot_plan_v2_20261030/cost_estimate.json)

- 6,480 original-question answers plus 2,880–3,840 source-grounded answers.
- 720 shared no-memory controls: twenty attack questions and sixteen safe-source
  questions per bag. Diagnostic controls outside the final probe cohort are not
  added to scored outcome denominators.
- At most 960 frozen query-classification responses. Sharing requires identical
  queries/prompts/model and actually provisioned common response catalogs.

- 1,200 logical audit tickets summed over all trajectories, or 300 per arm.
  The service has 300 shared scheduled jobs, but every arm still receives the
  same five-ticket budget. Oracle lookup is not a free real-world verifier.

The minimum uses no paid detector/verifier. Exact frozen memory reconstruction
must succeed offline: a miss aborts rather than paying for new records with stale
annotations. Existing local MiniLM handles embedding needs without a download or
paid fallback. Grounded QA scoring uses validated aliases and blinded human review
for semantic cases; no extra LLM QA judge is silently budgeted.

Annotation/adjudication labor, taxes, credit purchase fees and local compute are
unknown/excluded costs. This is not the total cost of a paper. New extraction and
reannotation, real verification, hyperparameter grids, optional references,
robustness suites, another model and full MPBench need separate estimates.

## Why scientific execution is not ready

Coverage was recomputed from the current raw two-reviewer/adjudicator and QA forms,
rather than trusting an editable readiness flag. It remains:

- **0 independently verified bundles/record-use labels.**
- **0 human-validated grounded questions.**
- 2,114 packets still missing two completed safety reviews.

The final pilot needs 640 distinct grouped inputs with the required per-domain
case strata and 320 independently safe plus 320 unsafe bundles, alongside one
independently validated grounded question for each of the 320 safe contributions.
Correct aggregate counts alone would still not prove group/template independence,
safe support, use-specific validity or complete audit/probe cohorts.

The final scientific lock therefore remains unavailable. Additional prerequisites
are exact real-case native graph bindings and response catalogs, prompt/local
embedding coverage, fixed cohort IDs/denominators, and integration of live response
capture with the durable spending guard. Step 10 currently accepts offline replay
clients only. A provisional case-intent group cannot substitute for Z annotation.

The user has authorized needed API work after an advance estimate. No new approval
flow was added. This task did not need paid calls, and the $125 proposal is not an
activated allowance. A later paid run must satisfy the actual execution prerequisites
and provide a refreshed estimate/bound before dispatch.
