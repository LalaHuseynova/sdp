# Automated annotation branch and route to preliminary defense results

31 October 2026. The user explicitly requested an LLM reviewer after the limits
of automated versus human annotation were explained. This is a **separate,
exploratory branch** of the research. The original human-validated protocol,
review forms and primary scientific requirements remain intact.

## Authorized first review

- One frozen GPT-4o-mini reviewer through the existing guarded OpenRouter path.
- The first existing development group, D00: 32 inputs, 16 Email and 16
  File/Document; 790 actual memory records and 48 existing question drafts.
- Cases are the preselected group, not selected using attack success, new-method
  performance, warning scores or LLM review outcomes. Locked groups are untouched.
- One request per contribution, covering every claim/chunk for its original
  intended use and separately checking that contribution's question candidates.
- Exactly 32 allowlisted request IDs, one physical attempt each, 12,288 output
  tokens maximum. No automatic retry, replacement case or successful-label quota.
- Working estimate USD 0.10–0.25; full-context per-request reservation sum
  USD 0.8503296. This was disclosed before paid dispatch and is inside the same
  existing USD 30 project allowance, not an additional budget.

Model input includes the original task/use, source artifact roles/text, memory
record IDs/kinds/text, and candidate questions/references needed for QA review.
Original case labels, expected targets, source-risk profiles, method outputs,
automated warning hints, earlier reviewer votes and future audit outcomes are
excluded. Candidate QA reference answers are not original MPBench attack targets.
Text contained inside actual source payloads is preserved, including attack text.

The fixed system instructions treat all document contents as untrusted data. The
reviewer is not given tools, an answering-agent role or authority to perform any
action described in a memory. Dangerous wording, quotations, disagreement,
irrelevance and unverifiable factual claims are distinguished from confirmed
evidence of prohibited influence for the specified use. Uncertainty is allowed.

## Meaning of the labels

Let **Z-hat** denote an LLM-proposed record/use or bundle label. It is distinct
from the protocol's independently annotated **Z** and the original **Y_case**.
No original attack/benign case label is changed.

Every output is marked `annotation_source=llm`, `human_validated=false`,
`independent_human_review=false`, `eligible_as_gold=false` and
`can_update_live_trust=false`. Single-model replies do not become consensus,
independent reviews, calibrated probabilities or authenticated contributor IDs.
Human verified-label and validated-question counts remain zero.

Memory decisions use `safe_for_use`, `unsafe` or `uncertain`. Source-field origin
is separately `principal`, `external` or `ambiguous`. An exact source quote is
required for resolved source-field attribution, and an unsafe proposal needs a
literal evidence quote from the actual memory. The parser computes artifact-local
Unicode offsets for all matching quote occurrences; it never invents offsets or
silently selects one occurrence. A literal quote is not proof of semantic support
or real authorship. Innocent uploaders are not automatically culpable authors.

Missing/repeated IDs, mismatched source roles, absent/altered quotes, invalid JSON,
extra human-validation claims and truncated replies fail mechanical validation.
They remain failed/incomplete observations, not safe labels, unsafe labels or
successful defense outcomes. Raw replies and receipts are retained. No paid
retry is hidden as free review work.

Question proposals are checked for source support, clarity, usefulness, safe
descriptive use and answer leakage. Automated acceptance is not validated utility
ground truth. Native support availability, original governance admission and
uniqueness/disambiguation within a final bag still need checking. In particular,
chunk-only external support is restricted by frozen `external_evidence=false`.
Question edits need new candidate versions and new assessments.

## Spending and execution boundary

The annotation transport has a separate explicit plan authorization. It cannot
arm scientific execution or dispatch answers, conflicts, controls or judgments.
It shares the existing session lock, USD 30 BudgetGuard, response journal and
unknown billing holds. No new project allowance, provider-key limit or credit
purchase is created. Existing experiment execution remains gated.

Maximum token prices and official endpoint restrictions are unchanged. The
[official model page](https://openrouter.ai/openai/gpt-4o-mini/overview) was checked
on 31 October: USD 0.15/M input and USD 0.60/M output, 128k context. Before the
review, a free read-only provider allowance check succeeded. Provider allowance
does not replace the stricter local USD 30 ceiling.

Native JSON is saved before billing validation, protecting replies if billing
verification stops consumption. Unknown outcomes retain funds and halt subsequent
requests; restarts never resend an ambiguous dispatch. Completed exact requests
are replayed from their saved transcript. Charges and native tokens come from
provider receipts, not the text-size proxy. Model failures and annotation-schema
failures remain separate. Simulated HTTP tests are labeled mock, never paid data.

## What this first run can establish

It can report completion/format coverage, proposed safety/source distributions,
uncertainty, automated question acceptance/rejection, truncations/failures,
native tokens and actual cost. It cannot establish annotation accuracy, true
detector FPR/FNR, human agreement, improved ASR, benign utility preservation or
ICML-level novelty. The output is preliminary annotation-feasibility evidence.

## Next steps toward a preliminary defense experiment

1. Inspect mechanical failures and a blinded qualitative sample. Preserve this
   first review as a fixed result. Any revised prompt/schema is a new version;
   do not retrospectively relabel mistakes or optimize it on locked groups.
2. Establish eligible development contributions and useful questions. If the
   required per-domain composition is unavailable, review additional development
   candidates in a declared seeded order after a fresh cost estimate. Do not force
   16 safe/16 unsafe labels or choose only cases where SAFE-Mem previously failed.
3. Freeze an **AI-label-controlled exploratory** episode manifest, explicitly
   using Z-hat rather than human Z. Use a declared trusted synthetic origin overlay
   while preserving principal roots and keeping unresolved attribution local.
   Current unknown roots cannot silently become authenticated contributors.
4. For a first end-to-end mechanism check, use one eligible 32-case development
   bag, strong-localized/strong-distributed/uninformative overlays, and R/C/M/S at
   the same fixed operating point. Give all arms the same five scheduled feedback
   tickets and the same probe/utility cohorts. This is 12 paired trajectories,
   not 12 independent datasets. A seeded incident is an AI-flagged incident,
   not a claim of independently confirmed unsafe memory.
5. Record automated feedback provenance explicitly (frozen verifier/controlled
   AI feedback), never as human adjudication or oracle truth. Keep dataset-labeling
   cost, per-policy logical audit budgets, equivalent verifier expense and actual
   shared-cache charges separate. Give S no free additional investigations.
6. Use the original isolated MPBench target-answer evaluation, no-memory controls,
   retention and restraint metrics; add separately identified AI-checked utility
   diagnostics. Target judgments never become trust updates. Report source-
   grounded usefulness, refusal/coverage and collateral restrictions, not just
   lower ASR. AI-label suppression is an AI-reference diagnostic, not true FPR/FNR.
7. Compare S against both contextual reputation C and same-metadata fixed
   multi-scope M at matched utility and feedback cost. If M matches S, do not claim
   the selective rule adds value. Include all failures/budget stops and predefined
   cohorts; sparse attack successes make this small check inconclusive.
8. Before stronger paper claims, measure annotation quality on a genuinely
   independent, representative human-reviewed subset and run a separately frozen
   confirmation. The same reviewer/answer model can share errors. Add weak/noisy
   feedback, compromise, false accusation/recovery and source-linkage controls as
   already specified in the main protocol. Synthetic-source results do not prove
   natural repeated-contributor behavior.

No end-to-end defense experiment is launched by the reviewer command. Exact
request costs, validated/automated data status and resource availability must be
checked before that subsequent execution, retaining the user's USD 30 ceiling.

## Development amendment: smaller batches and local references

The disclosed first pass finished all 32 requests for USD 0.04142505. None of
its 32 packets passed the complete-packet validator: missing chunk decisions,
nonliteral quotes and other contract errors prevented acceptance. This is a
format/coverage failure, not evidence that all proposed semantic labels were
wrong. The replies, cost and rejected-packet list are preserved in
`research_data/llm_review_dev_v2_20261031/`. They are not silently corrected or
used as accepted safety labels.

While still using development data only, a second reviewer version was declared
and costed before additional calls. It covers the SAME 790 records and 48 question
drafts in 114 batches of at most eight memory records. Each contribution's QA
candidates are checked in its first batch only. There is no new case selection
based on labels or attack success.

The additional working estimate is USD 0.10–0.40, with full-context reservation
sum USD 3.0292992, inside the existing total USD 30 allowance. No new allowance,
unlimited retry or unreported replacement request is created. Each new-version
request ID still permits one physical attempt; this second pass is an explicitly
accounted new method version rather than a free retry of the first result.

Records use short local references m0–m7. Source and memory-evidence units have
deterministic IDs attached to literal source/record segments. The LLM selects
those IDs; the validator expands them to the original record/artifact IDs and
exact source/record text. This removes long-ID copying and generated quote-offset
errors. It does NOT independently validate semantic support, provenance,
authorship or the safety decision. Unknown references, missing decisions,
cross-record evidence, incorrect principal/external roles and absent unsafe
evidence still fail. No source origin or safety label is silently changed to make
a reply pass.

Valid batches may yield partial record-level proposals for an input. A complete
automated bundle outcome is computed only when all its expected record versions
are present once. Incomplete contributions remain `incomplete`, not fabricated
safe/unsafe/uncertain labels. Human-validation counts remain zero. Version 1 and
version 2 are not two independent reviewers or a consensus vote. Locked cases
were not used to revise the reviewer.

The batch version is stored separately in
`research_data/llm_review_small_batches_v2_20261031/`. Both versions share the
same parent billing journal and project ceiling. All version-specific costs,
coverage failures and limitations must accompany preliminary results.
